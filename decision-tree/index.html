Sequence tools — even ones with AI reply-branching now — sort what a reply says. Silence isn't a reply, so it still gets the same step 3 every time. This maps every outcome of a send to a diagnosis, an action, and how it goes out — new thread, or a reply under the one that's already working.

vs

Diagnostic layer

Silence isn't one outcome — it's three, each with a different cause. Step 3 is written to match which one happened, before a reply ever comes.

Bounced

Diagnosis
The address is bad, not the message.
Action
Remove from the cadence, flag for list cleaning.
Mechanic
No further send.

Not opened

Diagnosis
Subject and preview line failed to earn attention. The body is untested — not proven bad.
Action
Full reset: new angle, new subject, new preview line.
Mechanic
New thread — a reply would carry the dead subject forward as "Re: …".

Miss twice in a row: stop and flag for a channel switch or an ICP check, not a third subject line.

Opened, no click, no reply

Diagnosis
Subject line is proven — it earned the open. The body or CTA didn't hold.
Action
Keep the subject pattern. Rewrite the body with a new angle or proof point.
Mechanic
Reply in the same thread — preserves the subject that already worked.

Clicked, no reply

Diagnosis
Strongest pre-reply signal — they engaged with the content, so relevance is established. The ask itself is the friction.
Action
Shorter, more direct CTA. No re-pitching the value prop.
Mechanic
Reply in the same thread.

Replied

Diagnosis
Conversation started.
Action
Hand off to whoever's running the deal.
Mechanic
Stop the automation.
